# 短信转发

将腾讯手机管家或 360 手机卫士的短信请求通过 Bark 转发，并使用 BoxJS 管理配置。支持仓库内的 Surge、Stash 和 Quantumult X 重写配置。

## 配置流程

1. 在代理工具中导入 `modle/` 下对应配置，并按客户端要求启用重写与 MITM。
2. 在 BoxJS 添加订阅：`https://raw.githubusercontent.com/Kry5ta1/sms_foward/main/js/tmp_boxjs.json`。
3. 打开「短信转发」，保持「① 基础 · 禁用脚本」关闭，选择短信来源，填写 Bark 的完整设备地址，例如 `https://api.day.app/YOUR_KEY`。
4. 保存配置，通过短信服务的实际请求触发。脚本不是定时任务，直接手动运行没有短信请求体不会发送通知。

Bark 地址为空时，仅显示本地预览。设备密钥属于敏感配置，请勿分享含密钥的 BoxJS 截图或配置导出。

## 容错与重试

- 默认首次请求失败后重试 2 次，单次超时 3 秒，间隔从 300 毫秒开始指数递增。
- 网络错误、超时、HTTP 408/429/5xx、无法确认成功的响应会重试。成功必须同时具有 HTTP 2xx 和 Bark 成功标记（`code: 200`、`code: 0` 或没有 code 时的 `isSuccess: true`）。
- HTTP 或业务响应中的其他 4xx 通常代表地址、鉴权或参数问题，立即停止，避免无效请求。
- 遵守响应中的 `Retry-After`；如果等待会超出预算，则停止本轮处理。
- 所有配置并行处理，共享约 16 秒预算，给宿主回写请求留出时间。最大重试次数是上限，不保证全部执行。宿主自身更短的执行限制仍可能提前终止。
- 最终失败只发送一次本地提示，不记录设备密钥、短信正文或验证码。单个配置错误不阻止其他配置。
- **超时不能证明服务端没收到请求，重试可能产生重复通知。** 这是当前进程内的有限重试，不是持久消息队列；进程退出或宿主终止后不会后台继续。

## 过滤规则

保留已有行为：同一维度中，允许规则是拒绝规则的例外，不是严格白名单。命中允许规则直接放行；未命中时再检查拒绝规则。号码和内容两个维度都通过才转发。

例如只想转发验证码：内容允许规则填 `验证码`，内容拒绝规则填 `.*`。正则表达式直接填写，不加 `/.../`。无效正则会跳过该配置并给出提示。

## 隐私与模板

- 「④ 隐私 · 替换原接口请求体」会把原请求体替换为 `{ "provider": "tencent", "redacted": true }` 等占位内容，**不会阻断网络请求**，也不会清除 URL、请求头或其他网络元数据；可能影响原接口功能。Bark 仍收到用于转发的短信内容。
- 数字脱敏仅对发往原接口的短信正文生效，不修改 Bark 消息。此开关不是加密或完全匿名化。
- 通知模板支持 `[号码]`、`[内容]`、`[时间]`、`[码]`、`[复制提示]`。
- 额外配置使用逗号分隔的名称，如 `work,personal`，读取 `@Kry5ta1.work.*`、`@Kry5ta1.personal.*`。需要自行准备这些存储配置；填写名称不会自动创建新的 BoxJS 表单。短信来源、原接口隐私选项和主暂停开关由 `sms_forward` 控制，过滤、模板、Bark 与重试设置由各配置控制。

## 验证

无需安装依赖，使用 Node.js 18 或以上：

```sh
node --check js/sms-forward.js
node --test tests/*.test.js
```

测试使用模拟的宿主存储、通知与 HTTP 接口，覆盖正常推送、失败重试、超时、配置隔离、隐私回写和 BoxJS 结构。不会发送真实短信。模拟通过不等于真实 iOS 客户端联调通过；最终请在目标客户端用不含真实验证码的测试短信验证。
